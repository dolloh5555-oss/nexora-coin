# NEXORA — Render deployment package

ชุดขึ้นออนไลน์แยกจากเว็บในเครื่อง ไม่รวมบัญชี รหัสผ่าน หรือฐานข้อมูลเดิม
ยังไม่ได้เผยแพร่ขึ้น Render และยังไม่ได้ตรวจผ่านโดเมนจริง

## วิธีขึ้นออนไลน์
1. แตก ZIP นี้ และสร้าง repository แบบ Private บน GitHub
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ โดย render.yaml, server.cjs, package.json อยู่ระดับบนสุดของ repository และ public อยู่ข้างกัน อย่าอัปโหลด data หรือไฟล์ .env
3. เข้าบัญชี Render เลือก New > Blueprint และเชื่อม repository ของคุณ
4. Render อ่าน render.yaml ให้ตรวจแผน Starter และดิสก์ 1 GB รวมค่าใช้บริการที่หน้า Render ก่อนยืนยัน การเผยแพร่จะทำให้หน้าตลาดเข้าถึงได้สาธารณะ
5. เมื่อบริการพร้อม เปิด URL ที่ Render แสดง หน้าแรกคือตลาดเหรียญ
6. เข้า Service > Environment ใน Render ดูค่า NEX_SETUP_TOKEN เก็บเป็นความลับ ห้ามใส่ใน GitHub หรือส่งในแชต
7. เปิด URL ของเว็บตามด้วย /admin กรอกรหัสเปิดระบบจากข้อ 6 พร้อมตั้งรหัสผ่านใหม่ 12–128 ตัวอักษรด้วยตัวเอง
8. หลังตั้งบัญชี ระบบจะปิดการสร้างบัญชีเพิ่ม การเข้าสู่ระบบครั้งต่อไปใช้รหัสผ่านผู้ดูแลเท่านั้น

## ค่าที่จัดให้
- Node.js 24, คำสั่งเริ่ม node server.cjs
- รับ PORT จาก Render และฟัง 0.0.0.0 ในโหมด production
- ใช้ RENDER_EXTERNAL_URL เป็นที่อยู่เว็บที่อนุญาต
- NEX_SETUP_TOKEN: Render สร้างค่าสุ่มผ่าน Blueprint
- NEX_DATA_DIR: /var/data/nexora อยู่ในดิสก์ถาวร
- /healthz: ตรวจบริการ, /: ตลาด, /admin: ผู้ดูแล
- HTTPS จบที่ Render; คุกกี้ผู้ดูแลมี Secure, HttpOnly, SameSite และชื่อ __Host-
- ตรวจ Host, Origin และ CSRF; ต้องมีรหัสเปิดระบบก่อนสร้างผู้ดูแล
- รันหนึ่ง instance/หนึ่ง process เนื่องจาก SQLite และ sessions อยู่ในหน่วยความจำ

## ตั้งโดเมนของตัวเอง
เพิ่มโดเมนและตั้ง DNS ตามหน้าจอ Custom Domains ของ Render รอ HTTPS พร้อม
จากนั้นเพิ่ม PUBLIC_ORIGIN เป็น https://ชื่อโดเมนของคุณ (ไม่มี path) แล้ว redeploy
เมื่อกำหนดแล้ว Host และ Origin อื่น รวมถึงโดเมน onrender.com เดิม จะถูกปฏิเสธ ยกเว้น /healthz
ห้ามใส่ PUBLIC_ORIGIN ตัวอย่างก่อนมีโดเมนจริง

## ข้อมูลและความปลอดภัย
นี่คือเว็บแสดงตลาดและระบบบริหารภายใน ไม่รับฝากหรือส่งเงิน ร้านขาย NEX ยังเป็นตัวอย่าง Swap ยังเปิด PancakeSwap ภายนอก
การขึ้นออนไลน์ไม่ได้ทำให้ระบบพร้อมรับเงินจริง ไม่มีการรับประกันความปลอดภัยแบบผ่าน audit
ไม่รวมระบบหลายผู้ดูแลหรือ MFA อัตราลองรหัสจำกัดร่วมทั้งระบบ 10 ครั้งต่อ 10 นาที อาจทำให้ผู้ดูแลรอเมื่อมีคนยิงคำขอผิดซ้ำ
เซสชันหมดหลัง 1 ชั่วโมง และหมดทุกครั้งที่รีสตาร์ต ไม่ได้สูญเสียข้อมูลฐานข้อมูล
เก็บ NEX_SETUP_TOKEN ไว้ใน Render ต่อไป การเริ่ม production จะตรวจว่ามีค่านี้เสมอ
ดิสก์ถาวรไม่ใช่ข้อมูลสำรอง: ให้ทำสำเนาฐานข้อมูลอย่างสม่ำเสมอด้วยวิธี SQLite backup หรือหยุดบริการก่อนคัดลอกไฟล์ฐานข้อมูลและไฟล์ WAL ที่เกี่ยวข้อง
อย่าลบดิสก์หรือเปลี่ยน NEX_DATA_DIR หากต้องการรักษาข้อมูล
ห้ามนำฐานข้อมูลเข้าระบบ Git หากต้องย้ายข้อมูลเดิมให้จัดการแยกผ่านช่องทางผู้ดูแลเซิร์ฟเวอร์
การแก้ไฟล์ static ใช้ public; แก้ระบบใช้ server.cjs แล้ว push GitHub
ภาพพื้นหลังต้นฉบับประมาณ 19 MB อาจโหลดช้าบนมือถือ ยังเก็บภาพเดิมตามที่ผู้ใช้เลือก

## ทดสอบ
npm test — ใช้ฐานข้อมูลทดสอบชั่วคราว ไม่แตะฐานข้อมูลจริง ทดสอบรหัสเปิดระบบ คุกกี้ Host/Origin/CSRF การยกเลิก session และข้อมูลหลังรีสตาร์ต
node server.cjs — ทดสอบในเครื่องที่ http://127.0.0.1:8771 เมื่อไม่มี NODE_ENV=production
